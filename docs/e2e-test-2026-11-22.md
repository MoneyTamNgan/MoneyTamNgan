## Change found since 19 Nov: export needs every checklist item to pass
The 19 Nov run exported a DOCX straight after creating a draft. `v1.0.0` returns **409 CHECKLIST_NOT_PASSED** until the owner has marked every checklist item as passed (`PATCH /api/bid-prep/tors/{id}/checklist`, as the UI does). The smoke test now checks both: blocked first, then allowed after all 47 items are marked (DOCX 64 600 bytes, valid zip). **Demo impact:** on a real TOR every item starts as `manual`, so export only works after the user confirms each item; do this beforehand on the demo draft.

## Checklist on different TORs (`tests/e2e/checklist-variants.py`, 25 TORs)
- 5 of 25 TORs have a checklist (11 to 24 items; with the made-up empty profile every item is `manual`, none pass or fail).
- 20 of 25 return 409 with no items: the TOR's extracted conditions are incomplete. This is the "incomplete data" case: a clean error, no crash, about 0.5 s.
- Clear / ambiguous conditions: not separable with an empty profile (every item is `manual`). A profile with real numbers would be needed to see pass/fail; not done.

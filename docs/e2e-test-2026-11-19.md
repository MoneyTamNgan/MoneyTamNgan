## What this covers

- Public pages and API as a guest: health, TOR list (838 TORs), detail, keyword search, facets.
- Accounts: register with email and username, login by email and by username, wrong password rejected, session, logout ends the session.
- Access control: guests get 401 on drafts and the admin API; a normal user gets 403 on the admin API and the `/admin` page.
- BidPrep: company profile edit, checklist (47 items for the sample TOR), create and read a draft, DOCX export (a valid zip of 66 KB), AI proposal draft queued and completed by the worker.
- Isolation with 2 accounts: account B gets 404 for account A's draft, export and AI job, and A's draft is not in B's list.

## Findings

1. **The session cookie is `Secure` in production** (`lib/auth.js`). A browser accepts it on `http://localhost`, but not when the app is opened by IP or host name over plain http, so login fails there. Demo from a browser on the machine itself at `http://localhost:3000`, or put the app behind https.
2. **The AI draft takes 76 to 92 s on this hardware** (GTX 1050 Ti, `qwen2.5:3b`), and 2 of 3 real TORs timed out at the 90 s cap in the [timing run](connectivity-test-2026-11-19.md). The queued job is asynchronous, so the page does not block, but the 90 s criterion of #139 is not met.
3. `/api/tors` returns 500 (not 503) while the database is down. It does not hang, but a 503 would be more accurate.

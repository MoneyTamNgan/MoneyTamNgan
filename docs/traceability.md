# Requirements traceability

This matrix connects each SRS requirement to the GitHub card, pull request, test and evidence file that support it. Paths were checked against the files in this repository. Card and pull-request numbers are the ones supplied with the matrix; GitHub issues were not edited.

## Requirement id convention

The Bid Preparation SRS numbers its requirements `FR-4.1` … `FR-4.7`. The main SRS already uses `FR-4.1.1` … `FR-4.2.2` for public analytics. Those are different requirements.

- Main SRS ids are written `FR-1.x`, `FR-2.x`, `FR-3.x`, `FR-4.1.x`, `FR-4.2.x`, and `NFR-1` … `NFR-6`.
- Bid Preparation ids are written `BidPrep FR-4.x` (for example `BidPrep FR-4.1.1`). The number after the prefix is the id printed in the Bid Preparation SRS. Nothing in code identifiers was renamed.

A bare `FR-4.1` in an older BidPrep note means `BidPrep FR-4.1` (company details for a bid), not main SRS `FR-4.1.x` (historical search).

## What was checked in the repository

- Every `tests/...` glob in the tables matches at least one file.
- Every evidence path in the tables exists. A directory link means that directory exists. The six `evidence/notification-*.json` files are linked on FR-2.3.3.
- `models/Project.js` has `project_id` unique, which is the FR-1.1.3 control. The ER diagram records that key as `project_id UK`.
- `lib/budget-anomaly.js`, `lib/flagged-clauses.js` and `lib/services/project-mapper.ts` implement the budget tag, flagged-clause reasoning and executive summary. The OpenAPI schemas for those three are marked Current.
- `lib/api/tor-response.js` returns `matchScore` for a signed-in caller. The 22 Nov UI sheet never asserts that number.
- `lib/egp-api.js` can read a contract `winner_name`. No test asserts that value as a stored historical attribute (FR-4.1.1).

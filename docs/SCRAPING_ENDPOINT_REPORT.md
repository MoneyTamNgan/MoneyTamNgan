## Executive summary

The complete scraping path worked successfully for project `67079116603`. The system resolved the project through the TOR aggregator, opened the encrypted official e-GP detail page, obtained the e-Bidding ZIP, downloaded it, extracted three PDFs, and selected the primary TOR PDF.

The scraper is nevertheless not reliable for every project. The aggregator does not always provide an official e-GP detail link, and the official e-GP document-list service can intermittently return an empty page, time out, or terminate a request.

## 4. e-Bidding ZIP-list service

The official detail page dynamically generates a request containing:

```text
/getTorZipList?...dynamic query parameters...
```

The current scraper captures the URL generated by the official application and repeats the request inside the same browser session with cookies enabled.

Observed result:

- The ZIP-list request succeeded.
- A list of e-Bidding archive versions was returned.
- The latest archive version was selected.

The complete URL is generated dynamically and should not be treated as a stable or bookmarkable endpoint.

## Confirmed working pipeline

```text
Open Data metadata API
  -> project ID
  -> aggregator project permalink
  -> encrypted official e-GP detail page
  -> e-Bidding document row
  -> dynamic ZIP list
  -> approval service
  -> official ZIP download
  -> secure ZIP extraction
  -> primary TOR PDF selection
```

## Known failure conditions

1. The aggregator page exists but contains no official e-GP detail link.
2. The official detail page initially renders an empty F5/anti-bot page.
3. The related-document table takes longer than the project metadata to render.
4. The `getTorZipList` request times out or is terminated.
5. Direct e-GP search encounters human verification.
6. A download URL requires browser-session cookies and a valid referrer.
7. The government service is intermittently slow or unavailable.

## Current assessment

The scraper works end to end for projects whose aggregator page contains a valid official-detail link and whose e-GP document services respond successfully. The main risk is intermittent external availability rather than ZIP extraction or PDF selection logic.

The test archive and extracted PDFs were stored only in a temporary directory and deleted after verification.
